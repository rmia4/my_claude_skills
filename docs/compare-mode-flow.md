# 비교 모드: 독립 답변 비교 흐름

- 상태: 구현·dry-run 검증 완료, 실제 CLI 확인은 남음 (2026-10-28)
- 범위: 비교 모드. 수동 모드는 [manual-mode-flow.md](manual-mode-flow.md), 자동 모드는 [auto-mode-flow.md](auto-mode-flow.md)를 따른다.
- 공통 규칙(파일 구성, 호출 실패, 저장·재개, dry-run)은 [common.md](common.md)를 따른다. 이 문서에는 이 모드에만 해당하는 규칙을 적는다.

## 목표

합의나 판정 없이, 사용자가 낸 질문·지시에 대한 두 AI의 답을 따로 받는다. 진행자는 두 답의 요약·공통점·차이점을 정리한다. 같은 토의 안에서 후속 질문을 이어 갈 수 있다.

## 역할

| 주체 | 맡는 일 |
|---|---|
| 사용자 | 시작 승인, 후속 질문, 종료 |
| 진행자 (토의를 호출한 Claude Code 세션) | 질문·배경 정리, 두 답을 읽고 분석 작성, 사용자의 말을 명령으로 옮김 |
| 스크립트 (discussion.mjs) | AI 호출, 상태 저장, 로그 기록 |
| Claude / Codex (새 세션) | 질문에 답한다. 다른 AI가 있다는 것을 모른다 |

진행자 원칙:
- 어느 답이 낫다고 평가하지 않고, 주제에 대한 자기 의견을 내지 않는다.
- 분석은 두 AI가 쓴 내용에서만 옮긴다. 새 내용을 더하지 않는다.
- 다른 모드와 달리 분석을 위해 그 차례의 raw 두 파일을 읽는다. AI 답 전문은 채팅에 옮기지 않고 링크로 남긴다.

## 진행 흐름

```
0. 준비     진행자: 질문(지시)·배경·참조 정리 → [사용자: 시작 승인] → start
1. 답변 T1  두 AI가 동시에 따로 답한다 (JSON 없음)
2. 분석     진행자: 두 raw를 읽고 요약·공통점·차이점 작성 → analysis
3. 후속     사용자 후속 질문 → ask → 답변 T2 → 분석 … (반복)
4. 종료     end
```

## 프롬프트

- 다른 AI를 언급하지 않는다. "아래 질문에 답하라"로 시작하고 배경·요구사항·참조 자료를 붙인다. workdir가 있으면 다른 모드와 같은 파일 읽기 원칙을 주되, 작업 성격은 "질문에 답하는 작업"으로 적는다.
- 후속 차례에는 이전 질문과 **그 AI 자신의** 이전 답을 차례대로 붙이고, 마지막에 이번 질문을 붙인다. 상대 답은 넣지 않는다(독립 유지).
- 응답은 본문만 받는다. JSON 블록이 없으므로 형식 오류 재시도도 없다.

## 분석 형식

```markdown
## 요약
## 공통점
## 차이점
| 항목 | Claude | Codex | 차이 종류 |
```

차이 종류는 결론 다름 / 한쪽만 다룸 / 근거·전제 다름이다. 형식 검사는 하지 않는다(비어 있지 않은지만 본다).

## state.json

```json
{
  "mode": "compare", "topic": "첫 질문", "background": "...", "requirements": ["..."],
  "context_files": [], "workdir": null, "claude_model": null,
  "status": "running", "pending_step": "answer", "halt_reason": null,
  "turns": [{"n": 1, "question": "...", "answers": {"claude": "...", "codex": "..."}, "analysis": "..."}]
}
```

- `pending_step`: `answer`(마지막 차례 답변 대기) 또는 null(다음 질문 대기).
- `turns[].answers`는 두 AI가 모두 성공해야 채워진다([common.md](common.md) "저장 시점과 재개").

## 파일

- raw: `raw/t<N>_claude.md`, `raw/t<N>_codex.md`
- 분석: `t<N>_analysis.md` (다시 쓰면 덮어쓴다)
- log.md: 차례마다 질문, 두 답, 진행자 분석(제목은 한 단계 내려 넣는다). 분석을 고쳐 쓰면 "(고쳐 씀)"으로 덧붙인다.

## 하위 명령

| 명령 | 하는 일 |
|---|---|
| `start --spec spec.json` | 토의를 만들고 T1 답변 실행. spec의 `topic`이 첫 질문이다 |
| `ask <id> "질문"` / `ask <id> --file q.md` | 새 차례를 붙이고 답변 실행. 답변 대기 중이거나 끝난 토의면 거부 |
| `analysis <id> --file a.md [--turn N]` | 진행자 분석 기록. 기본은 마지막 차례. 답변이 없는 차례면 거부 |
| `next <id>` | 중단된 답변 단계를 다시 실행. 대기 중인 단계가 없으면 거부 |
| `end <id>` | 종료 |
| `show <id>` | 차례별 질문·raw 링크·분석 유무와 쓸 수 있는 명령 |

- AI를 부르는 명령(`start`, `ask`, `next`)은 스킬에서 백그라운드로 실행한다.
- 다른 모드 전용 명령(`judge`, `run` 등)은 거부된다. `end`는 수동 모드와 같이 쓰며 모드에 따라 나뉜다.

## dry-run

- 가짜 응답은 `(Claude) T1 답변`처럼 이름과 차례만 담는다. 시나리오는 `callfail`(호출 실패 → 중단)만 의미가 있다.
- 검증(2026-10-28): 시작 → 분석 → 후속 질문(텍스트·파일) → 프롬프트에 상대 답이 없음 확인 → 호출 실패로 중단 → `next` 재개 → 종료, 그리고 거부 경로(다른 모드 `--mode`, 수동 모드 명령, 대기 중 `ask`, 없는 차례 `analysis`, 끝난 뒤 `ask`).
