# 진행자 공통 규칙

모든 모드 스킬이 시작할 때 읽는다. 모드마다 다른 값(`<모드>`, AI를 부르는 명령, 재개 명령, spec 필드)은 각 스킬에 있다.

## 명령 실행

- `$SCRIPT`는 이 파일이 있는 폴더 기준 `../scripts/discussion.mjs`의 절대 경로다.
- 모든 명령: `node "$SCRIPT" <명령> <id> ... --mode <모드>`. **`--mode <모드>`는 `start`를 포함해 항상 붙인다**(스킬의 예에서는 생략한다). `start`는 `start --spec <파일> --mode <모드>`로 쓰고, spec의 mode가 다르면 스크립트가 거부한다. 다른 모드의 토의면 스크립트가 거부하고 맞는 스킬을 알려 준다. 그대로 사용자에게 전한다.
- `<id>`는 `last`(가장 최근 토의) 또는 사용자가 지정한 토의 이름을 쓴다.
- **AI를 부르는 명령(스킬에 적혀 있다)은 Bash `run_in_background: true`로 실행**하고 끝났다는 알림을 기다린다. 기다리는 동안 폴링하지 않는다. 나머지 명령은 바로 실행한다.
- 진행자가 넘기는 파일(spec, 쟁점표, ops, 질문, 분석, 최종안)은 scratchpad 폴더에 만든다. 토의 기록은 현재 작업 폴더의 `discussions/<id>/`에 쌓인다.
- 중단·재개: 출력에 "상태: 중단"이 나오면 사유를 알리고, 스킬에 적힌 재개 명령으로 같은 단계를 다시 실행한다. 상태가 헷갈리면 `show`로 다시 본다.
- 이 폴더의 설계 문서 `common.md`와 `<모드>-mode-flow.md`는 스킬의 절차로 판단이 서지 않을 때만 읽는다.

## 시작 준비 (사용자 승인 필요)

1. 주제(질문·지시)·배경·요구사항을 정리한다. 답하는 AI는 대화 맥락을 모르므로 이 내용이 전부다. `/ai-discussion:start`가 넘긴 입력(args)이 있으면 그대로 쓰고 빠진 것만 보완한다. 이미 받은 내용을 다시 묻지 않는다.
2. args에 진행 중인 토의 id가 있으면 새로 시작하지 않고 `show <id>`로 이어 간다.
3. 정리한 내용을 채팅 본문으로 보이고 시작 승인을 받는다. 승인 질문은 본문 끝에 적고 턴을 끝낸다.
4. 승인되면 spec 파일을 쓰고 `start --spec <파일>`을 백그라운드로 실행한다.
   - 필드는 스킬에 적힌 spec 필드를 쓴다.
   - `context`에는 큰 파일 전문 대신 필요한 부분만 발췌해 넣고, 발췌마다 원래 경로와 줄 번호를 적는다. 원문 전체가 필요하면 `workdir`를 주어 참가자가 직접 읽게 한다.
   - start에서 넘어왔으면 `"via": "start"`를 넣는다.
   - 스킬에 적힌 선택 옵션은 사용자가 요청할 때만 넣는다. 예를 들어 참가 모델을 지정하면 `claude_model`, 토큰 사용량을 알려 달라고 하면 `usage`를 넣는다. 옵션의 뜻은 `$SCRIPT` 맨 위 주석의 "spec.json 예"(앞 30줄)에서 확인한다.
